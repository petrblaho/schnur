# Schnur Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the two load-bearing infrastructure pieces the Scribe architecture depends on — UUIDv7 primary keys and per-Game serialized background processing — before any domain schema exists.

**Architecture:** Add the `uniq` library and expose UUIDv7 as the default primary/foreign key type through a single shared `Schnur.Schema` macro module that every future Ecto schema will `use`. Add Oban configured with a `scribe` queue at `concurrency: 1`, wired into the application supervision tree. No domain tables (`Game`, `Note`, `Node`, etc.) are created here — this plan only lays the infrastructure and proves it works with focused tests.

**Tech Stack:** Elixir 1.20 / OTP 29, Phoenix 1.8, Ecto SQL 3.13, PostgreSQL (Postgrex), Oban 2.23, Uniq 0.6 (UUIDv7).

## Global Constraints

- Elixir `~> 1.20`, OTP 29 (`mise.toml`: `erlang 29.0.5`, `elixir 1.20.3-otp-29`).
- Database: **PostgreSQL only** (`Ecto.Adapters.Postgres`). Dev port `5433`; test port from `DB_PORT` env (default `5433`).
- Primary keys: **UUIDv7** for all tables (spec §Architecture/IDs — time-ordered IDs double as chronological ordering key).
- HTTP client: `Req` only. Never `:httpoison`, `:tesla`, `:httpc`.
- Background processing: **Oban**, `scribe` queue at **`concurrency: 1`** (spec §Architecture — serializes Scribe work so processing order matches append order).
- `mix precommit` must pass clean: `compile --warnings-as-errors`, `deps.unlock --unused`, `format`, `test`.
- Migrations created via `mix ecto.gen.migration <name>`.
- Commit style: Scoped/Conventional Commits (`feat:`, `deps:`, `config:`, `docs:`, `schema:`).
- CI PLT cache key already includes `mix.exs` + `mix.lock`; adding deps triggers exactly one correct PLT rebuild+save on CI.

### Task 2: Introduce a shared `Schnur.Schema` macro that defaults to UUIDv7 keys

This module is the single place UUIDv7 is wired in. Future domain schemas will `use Schnur.Schema` instead of `use Ecto.Schema`. **Coverage decision (avoids CI red on the 90% gate):** `lib/schnur/schema.ex` is a pure
configuration macro with no runtime logic of its own (its `__using__` body only sets module
attributes). Like `application.ex`, `repo.ex`, and `mailer.ex` — already in
`coveralls.json` `skip_files` — it has nothing meaningfully testable and would otherwise count
as uncovered `lib/` code once the throwaway probe test is deleted. Add it to `skip_files` in
this task (Step 1a). The probe still verifies real behavior during development; deleting it
then has zero coverage impact because the file is skipped. This keeps the "no domain tables"
invariant AND keeps `mix coveralls` green.

**Files:**
- Create: `lib/schnur/schema.ex`
- Modify: `coveralls.json` (add `lib/schnur/schema.ex` to `skip_files`)

- Create (temporary, deleted in Step 8): `priv/repo/migrations/<generated>_create_schema_probe.exs`

**Interfaces:**

- Produces: `Schnur.Schema` — used via `use Schnur.Schema`, setting `@primary_key {:id, Uniq.UUID, version: 7, autogenerate: true}`, `@foreign_key_type Uniq.UUID`, `@timestamps_opts [type: :utc_datetime]`.

- [ ] **Step 1: Write the shared schema module**

Create `lib/schnur/schema.ex`:

```elixir
defmodule Schnur.Schema do
  @moduledoc """
  Base schema conventions for all Schnur Ecto schemas.

  Use this in place of `use Ecto.Schema`. It configures:

    * UUIDv7 primary keys (`Uniq.UUID`, `version: 7`) — time-ordered IDs that
      double as a chronological ordering key (see core architecture spec).
    * UUID foreign keys, so associations line up with the UUIDv7 primary keys.
    * `:utc_datetime` timestamps, matching the project's generator config.

  ## Example

      defmodule Schnur.Campaigns.Game do
        use Schnur.Schema

        schema "games" do
          field :name, :string
          timestamps()
        end
      end
  """

  defmacro __using__(_opts) do
    quote do
      use Ecto.Schema

      @primary_key {:id, Uniq.UUID, version: 7, autogenerate: true}
      @foreign_key_type Uniq.UUID
      @timestamps_opts [type: :utc_datetime]
    end
  end
end
```

- [ ] **Step 4: Write the failing test**

Create `test/schnur/schema_test.exs`:

```elixir
defmodule Schnur.SchemaTest do
  use Schnur.DataCase, async: true

  alias Schnur.SchemaProbe

  test "primary keys are autogenerated as version 7 UUIDs" do
    {:ok, row} =
      %SchemaProbe{}
      |> Ecto.Changeset.change(%{label: "first"})
      |> Repo.insert()

    assert {:ok, %{version: 7}} = Uniq.UUID.info(row.id)
  end

  test "generated ids round-trip through the database as valid v7 UUIDs" do
    {:ok, a} = %SchemaProbe{} |> Ecto.Changeset.change(%{label: "a"}) |> Repo.insert()

    reloaded = Repo.get!(SchemaProbe, a.id)

    assert reloaded.id == a.id
    assert {:ok, %{version: 7}} = Uniq.UUID.info(reloaded.id)
  end
end
```

> **Why not assert `a.id < b.id`?** `uniq`'s UUIDv7 fills the sub-millisecond bits with
> random data, not a monotonic counter. Two inserts microseconds apart routinely share
> the same millisecond, so lexical ordering between them is random — that assertion would
> flake ~50% of the time it collides. We assert the real invariant (valid v7, DB round-trip)
> instead. Time-ordering at millisecond granularity is a property of UUIDv7 itself, not
> something this suite needs to re-prove per-insert.

### Task 3: Configure Oban with the `scribe` queue at concurrency 1

Wire Oban into config and the supervision tree. The spec requires per-Game serialization at `concurrency: 1`; with one global Scribe in v1 we define a single `scribe` queue at concurrency `1`. Per-Game partitioning within that queue is enforced later by the Scribe worker (deferred with the Scribe loop).

> **⚠️ Boot-ordering hazard — do the steps in order and do NOT run `mix test`
> mid-task.** Oban's `start_link/1` calls `verify_migrated!` at application boot
> whenever `testing != :disabled` (verified in Oban 2.23.1 source: `lib/oban.ex`).
> That means once Oban is added to the supervision tree (Step 5), booting the app in
> ANY environment requires the `oban_jobs` table to already exist, or startup crashes
> with a migration error — which would break the *entire* test suite, not just the
> Oban test. This task is ordered so the migration (Step 3) is created and applied
> (Step 4 for dev; the `test` alias's `ecto.migrate --quiet` for test) BEFORE the
> supervision wiring (Step 5) and any test run (Steps 6-7). Follow the order exactly.
> Note also: adding the `config :schnur, Oban` block alone (Steps 1-2) does NOT boot
> Oban — the supervisor only starts once Step 5 adds it to `children` — so there is no
> hazard between Steps 1 and 4.

**Files:**
- Modify: `config/config.exs` (add `config :schnur, Oban, ...`)
- Modify: `config/test.exs` (Oban `testing: :manual`)
- Create: `priv/repo/migrations/<generated>_add_oban_jobs_table.exs`
- Modify: `lib/schnur/application.ex` (add Oban to `children`)
- Create: `test/schnur/oban_config_test.exs`

**Interfaces:**
- Consumes: `Oban` (Task 1), `Schnur.Repo`.

```elixir
defmodule Schnur.Repo.Migrations.AddObanJobsTable do
  use Ecto.Migration

  # For a fresh install, call up/0 and down/0 with NO version pin so Oban
  # migrates to its own latest schema version (v13 in Oban 2.23.x). Pinning a
  # version here (e.g. version: 12) would freeze the schema below the library's
  # current version and silently omit later migrations. Per Oban.Migration docs.
  def up do
    Oban.Migration.up()
  end

  def down do
    Oban.Migration.down()
  end
end
```

Create `test/schnur/oban_config_test.exs`:

```elixir
defmodule Schnur.ObanConfigTest do
  use ExUnit.Case, async: true

  test "the scribe queue is configured at concurrency 1" do
    config = Application.fetch_env!(:schnur, Oban)
    assert Keyword.fetch!(config, :queues) == [scribe: 1]
  end

  test "oban uses the Schnur repo" do
    config = Application.fetch_env!(:schnur, Oban)
    assert Keyword.fetch!(config, :repo) == Schnur.Repo
  end

  test "oban runs in manual testing mode" do
    config = Application.fetch_env!(:schnur, Oban)
    assert Keyword.fetch!(config, :testing) == :manual
  end

  test "the Oban instance is running (started by the supervision tree)" do
    # `Oban.config/0` looks the running instance up in Oban's Registry (in-memory,
    # no DB) and raises if no instance named `Oban` is supervised. So a non-raising
    # call is a real assertion that Oban is wired into the app's supervision tree —
    # stronger than inspecting the supervisor child list, and safe from a plain
    # `ExUnit.Case` (no Ecto sandbox needed). Under `testing: :manual` Oban's
    # supervisor still starts (it only sets queues: [] and plugins: []), so the
    # instance is registered. We assert the struct type only, not internal field
    # shapes, to avoid coupling the test to Oban's private config layout.
    assert %Oban.Config{} = Oban.config()
  end
end
```
